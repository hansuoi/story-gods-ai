# 第1話・完成原稿の制作プロセス

**版:** v1.0（2026-10-18）  
**適用:** 『神谷家 - 原状回復 -』第1話 P01–P32 の完成原稿（主な成果物は画像）  
**目的:** 読書検証用SVGを微修正し続ける状態から脱却し、実際に読める完成原稿を1ページずつ採用する。**プロセス自体も実測に基づき改善する。**

## 0. 前提・優先する原典

1. [脚本](../../../scripts/episode-01.md) / [文字ネーム](../../../name/episode-01.md): 場面・時系列・人物・台詞・コマの順番とページ境界。
2. [キャラクターデザイン](../../../design/character-study-v01.md) / [画面設計](../../../design/visual-direction.md) / [登場人物設定](../../../characters/README.md): 人物の外見・服装・振る舞い。
3. [連続性](../continuity.md) / [扉の機構](../door-mechanism.md): 水位・位置・機構・行為の因果。
4. [読書検証版](readproof/reader.md): レイアウト・情報の出し方を参考にする**試作品**。それ自体を完成画像とみなさない。
5. 原作の公開参照: https://ukigmo.work/works/gods01/ 。原作の非公開リポジトリの情報やURLを公開しない。

記述に矛盾があれば**脚本・ネームと人物設定の内容を優先し、恣意的な補完はしない**。仕様変更は制作記録へ理由を残す。

## 1. 成果物とファイルの役割

- **完成候補:** `docs/art/episode-01/finish/final-candidates/pNN/` に画像ファイル、候補仕様、生成・加工の記録を置く。仮置きと分かる命名にする。
- **完成採用:** `docs/art/episode-01/finish/final/pNN.png` （または原画を劣化させない形式）と、対応する採用記録。**完成候補は自動的に完成採用へ昇格しない。**
- **読書検証:** `finish/readproof/pNN.svg` は構図の参考・比較資料。今後の主たる仕上げレーンにはしない。
- **台詞:** 完成候補の生成時は原則文字を入れず、**日本語の正確な台詞・効果音を後工程で独立したレイヤーとして組版**する。ページの視線誘導に合わせて吹き出し位置を制御する。
- **進捗:** [STATUS.md](readproof/STATUS.md) に採否と理由、実画像の閲覧根拠、原稿コミット、書き出し検証結果を記録する。進捗ログ更新のみ・CI成功のみは原稿進捗に含めない。
- 画像生成から候補を作っても、GitHubへの画像登録に失敗したときは**登録済みと偽らず**、生成した画像を別途保持し障害を記録する。

## 2. 表現媒体

- **カラーを許可し、まずカラーで制作を検証する**。モノクロ縛りは設けない。P01–04では豪雨の寒色、照明、肌・白シャツの対比など、カラーによる空間理解を利用する。
- ただし、色の美しさより**人物の同一性・遠近・行為・読書性**を優先する。白黒でも人物・小道具が見分けられる形状を維持する。
- 原則として**デジタル単ページ**に最適化する。見開き配置は別途ページ境界のネタバレを点検する。
- 漫画の様式（絵柄、塗り、コマ線、背景密度）をP01で具体化し、後続ページへスタイル・リファレンスとして引き継ぐ。1画像に32ページ、あるいは複数ページを詰めて生成しない。

## 3. 1ページの制作サイクル

### A. ページ仕様を固定する（制作前）

`final-candidates/pNN/SPEC.md` に以下を明記する。

1. ページの役割（読者が何を見て、何を感じ、何を知らないまま次へ進むか）。
2. コマ数と**コマごとの**登場人物、姿勢、手、視線、背景、光源、カメラ位置、台詞・効果音、読書順。
3. 変えてはいけない設定、前後ページの位置・時刻・衣装・小物・能力の連続性。
4. 色調と正確な文字組み、想定読書サイズ、具体的な**不採用条件**。

### B. 絵を制作する（旧SVGへの微修正ではない）

1. 可能なら**1ページの無文字ラフ画像**でコマの意図と画風を検証する。1回目でコマ数・場面・人物を取り違えたら、細部を磨かず即不採用。
2. 全ページ一括生成が不安定なら**背景 → 登場人物リファレンス → コマ別画像 → ページへの配置**に分割する。生成画像には任意の日本語文字を書かせず、別レイヤーで正しく組版する。
3. 連続する人物には採用したキャラクターシートや直前ページの顔・衣服・色の参照を与える。AIが別人に描き替えた画像は破棄する。
4. 手指と接触箇所、空間・機械構造、コマ間の動作は**部分再生成・画像編集・再構成**する。小さな線や形のSVG修正のみで完成を目指さない。
5. 色の調整・効果・台詞・効果音を合成して**1枚の漫画として読める画像**にする。元画像とテキスト層は可能な限り保管し、修正可能にする。

### C. 検証・採用判定

1. **内容:** ページ番号、年、場面、人物、手足の数、衣装、隠すべき情報、能力制約がすべて正しいこと。
2. **演出:** 意図したコマ数・読む順番・視線移動・ページ境界の引きが成立すること。
3. **画面:** 人物の顔・解剖、衣服、手と物の接触、環境の立体感、光源・水位・遠近が成立し、機械・家具が一枚の図としてつながること。
4. **文字:** 文字化け・誤字なし。台詞が脚本・ネームに一致し、吹き出しと対応。縮小表示でも読めること。
5. **連続性:** 前後ページの人物と場所の一貫性。P01–04では榊の顔をP01に出さない、棒付きキャンディーはP02で初登場、切断するのは保持ピンのみ、レバーは人が操作し、少年を人が救う。
6. **実画像:** ページ全体を単ページ読書サイズで通読、必要箇所を拡大して確認する。可能なら前後を並べて連続確認する。
7. **検証証跡:** 原稿画像の版・SHA/ハッシュ、確認した画像の保存先、問題、判定、GitHubコミット・CIのURLを残す。

**採用基準:** 1–7をすべて満たし、試作ではなく完成原稿として掲載できること。不明・未検証なら必ず未採用。自動検査の成功は「描画工程が動いた」証拠に過ぎない。

## 4. 小さな改善サイクル（ページ単位、実行単位）

各制作セッションで、原稿作成の後に**手段の評価も実施**する。

- **観測:** 完成採用ページ数、実質的に修正したページ数、失敗した生成回数、失敗の種類（別ページ生成、設定逸脱、誤字、人体、構図、水位・部品、ツール書込）。
- **仮説:** 失敗の原因を特定（プロンプトの曖昧さ、ページ単位の負荷、参照不足、文字生成混入、合成不足など）。根拠のない「次はうまくいく」は改善ではない。
- **施策:** 次回に変更する変数を**明示**。例: 1ページ生成からコマ単位へ、文字なし生成へ、キャラシート固定へ、背景と人物を分割。
- **検証:** 変更前後で「設定逸脱の数」「実画像の合格項目」「完成採用の増分」を比較する。評価できない場合は「未検証」と書く。
- **標準化:** 改善できた手法だけ本書へ反映。効果が出なければ元に戻すか別手法へ変更する。

**停止条件・切り替え条件:**
- 同じプロンプトや構成で**2回続けて別ページ・別作品・図表・誤った出来事**が生成されたら、同じ条件での生成を停止し、**1コマ単位／無文字生成／個別参照**へ分割する。
- **同じページを3回修正しても完成条件が改善しない**場合は、局所編集を止めてページ再設計または制作手段の変更を行う。
- 生成ができても保存・画像検査ができなければ「完成」と宣言せず、障害を記録する。
- 追加課金のある外部API・有料ランナーを勝手に使わない。

## 5. 正式なステータス

- `not-started`: 完成原稿レーン未着手。SVGラフがあるだけでは着手としない。
- `spec-ready`: ページ仕様が記録済み、完成画像未制作。
- `art-candidate`: 実際の画像候補が制作され、参照可能。完成合否は未定。
- `revising`: 実画像の問題を検出して修正中。
- `accepted`: 実画像検証・連続性・台詞組版を経て正式採用。
- `blocked`: ツール・権限・素材不足。障害と迂回案を記録。

**「完成原稿を作り始めた」ことと「完成採用」は別。** 成果物がない仕様書のみの場合は `spec-ready` とする。

## 6. 第1話P01を最初の実験とする

[初稿制作仕様](final-candidates/p01/SPEC.md)を先に作る。**2024年の豪雨・地下歩道・3コマ**が一目で分かり、少年の手は届かず、救助員が扉を開けられず、榊は顔と棒付きキャンディーを出さずに革靴で踏み込む。カラー生成は手段であって目的ではない。1枚の漫画として採用できる画像になってからP02以降の標準にする。

この工程の前提に関する更新は[共通ビジュアル方針](../../../design/visual-direction.md)へリンクし、品質上の具体的な結果は[STATUS.md](readproof/STATUS.md)と当該ページの候補記録へ保存する。
